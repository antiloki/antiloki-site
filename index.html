L

LeaderYour terminal agent. Designs the team with you. Exactly one per graph.

A

AgentPlanner, worker, QA, debugger, audit, or your own agent with its own brief.

T

ToolWeb, files or an MCP server, with an allow-list the node must name.

F

Fork and joinBranches run side by side. The join waits for all, or for a quorum.

?

If and switchRoute on what a node said. A switch needs a default port.

O

LoopRepeat until a condition holds. It needs a max count and a cost cap.

E

For eachOne branch per item, in parallel up to a limit you set.

R

RetrySend a failed node round again, then take the exhausted port.

G

Gate and cost capA human gate waits for your yes or no. Any node can carry a cost cap.

D

Artifact and deliverThe documents a run makes, and the end of the graph: the pack reaches you.

What is vibe graphing?

Describing the work in plain words and getting a graph back: the Leader drafts a team as nodes and edges (agents, tools, forks and joins, checks, loops, gates), you edit it on the board, and the loop runs it under the budget you set. Every node is visible while it works and is recorded afterwards, so the graph is both the plan and the proof of what ran.

What is antiloki, in one sentence?

An agentic graph engineering loop IDE: a desktop workspace where a team of coding agents is drawn as a graph and run in a loop. It runs on the model subscriptions you already have — Claude, Codex, Cursor, Gemini, Grok — and sends each job to the seat measured best for it, with folder-level write enforcement, a verifier on every task, a confidence reading on every result, an optional independent QA and a full audit timeline.

Is it really free? What is the catch?

There is no catch in antiloki: no paid tier, no trial that ends, no account. The only costs are the model subscriptions or API keys you choose to use, and those are billed by their vendors. We plan to publish the source, so you can check that nothing is hidden.

Does it replace Claude Code, Codex, Cursor, Gemini or Grok?

No — it runs them, twice over: as the agent in its box, and as the engine behind antiloki's own AI (the chat, the reviews, the ultra review), each through its own vendor CLI. Keep your subscriptions; there is no API key to paste.

What does the X-ray do that a linter doesn't?

It judges every file against your rules and its own measurements (tests, coupling, structure, change) and tells you why a file is not 100. Then the ultra review: a $0 survey of the territory, and your engine reading the worst units to report what it can verify — with the fix. The chat sees all of it, so "why is this file 81?" gets a real answer — and the intel handed to an agent says which files it could not read.

Do I need two subscriptions?

For a merge, two usable seats. A merge never puts two frontier models together; it puts cheap hands under a good brain. Google's free tier is capped at a small daily number of agent requests (about twenty when we checked) — enough to try, not a seat to rely on. antiloki only offers a provider you are actually signed in to: it reads the seat, not the installed binary, so a CLI sitting on your machine unauthenticated is never offered as something it can bind. With one seat it runs solo — still routed per job, still tested, just not merged.

Isn't this just worktrees and tmux?

Worktrees are the easy part. The fence enforced where the work lands, the verifier before merge, the confidence reading with its optional QA, and the cost-per-task record are what you can't script in an afternoon — and what the graph records on every run.

Why is the benchmark measured against Opus?

Because Opus is the model an average developer reaches for all day, so "cheaper than what you run now" is the gap to it. The comparison is always raw Opus, one session, against the seat antiloki's router picks for the same task, both audited by the same hidden checks (list prices, per run): one function $0.168 vs $0.020 (8.3×, same speed, 14 vs 13 runs); eight modules $0.614 vs $0.060 (10.2×, 2.2× faster; the Opus figure blends this week's $0.443 with an older $1.151, newer runs weighted more, and on this week's alone it is 7.4×); six screens $0.644 vs $0.146 (4.4×, 1.1× faster); a huge task $1.83 vs $0.30 (6.2×, 1.5× faster, 1 vs 24 runs). The geometric mean is about 6.9× cheaper, with Composer 1.4× faster on average. What it leaves out, said plainly: the picks scored 0.95–1.00 of the checks against Opus's 1.00; the best cases route to Cursor's Composer, and without a Cursor subscription the average is about 3×; the figures are the routed model's cost, and the screening and verification antiloki adds cost a few cents on a small task and more on a large one (we are still measuring the full run end to end on the same tasks); the samples are small and from one project family. Against a cheaper raw seat the gap is smaller: raw Sonnet $0.166 and raw Codex $0.149 on the eight-module task. The full report lists every arm, including the ones that lost.

Does it make my weekly limit last longer?

The +590 % is arithmetic on measured costs, not a reading of your vendor's limit (the vendors do not publish it, and we have not measured yours). On the same spend at list prices, a job that costs 6.9× less lets you run 6.9× as many jobs: +590 %. The 6.9× is the geometric mean, over four audited tasks, of raw Opus against the best result of the Composer seat antiloki's router picks, with recent runs weighted more than old ones (a run loses half its weight every 14 days): one function 8.3×, eight modules 10.2×, six screens 4.4×, a huge task 6.2×. It assumes your limit scales with list-price cost, and the best cases route to Cursor's Composer; without a Cursor subscription the average is about 3× (+200 %). The picks scored 0.95–1.00 of the audit checks against Opus's 1.00, which is what "the same code quality" means here: inside the product's one tolerance. An earlier figure on this page (+112 %) compared one Sonnet-planned merge with raw Sonnet and did not reproduce with current models.

More calls must mean a bigger bill.

Sometimes they do, and the app shows it: the bill is on screen for every turn. A task that fits one cheap seat is run on that seat with one call and no planning; the router splits an ask only where splitting measured better, and a failed run reports what it spent and claims no saving. On the eight-module task the fully split pipeline cost more than raw Opus (about $0.78 against $0.44), which is why the router does not use it there.

Can my company install it?

One binary, local, no account, no telemetry. The network calls are: your CLIs' own calls; an update check against a static file on GitHub Releases; the window's fonts, fetched from Google Fonts (fonts.googleapis.com and fonts.gstatic.com) when it opens; api.openai.com or openrouter.ai only if you set up the optional OpenCode route with your own key; and GitHub only if you add a token or open a pull request. Send that to security.
