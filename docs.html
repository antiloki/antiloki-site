antiloki · documentation

antiloki docs.

Everything the desktop app does, in the order you meet it: install, set up, work, and what to do when something does not behave. Written for the current version.

1. Start here

antiloki is a desktop app that turns the AI subscriptions you already pay for (Claude, Codex, Cursor, Gemini, Grok) into one coding agent. You ask for a change in plain words; antiloki decides which of your subscriptions should do each part of it, lets them work in safe copies of your project, checks the result, and shows you what it did and what it cost.

It does not replace those tools and it has no model of its own. It runs each one through its own command-line program, signed in the way you already are, so there is no API key to paste and no extra account.

1 · Ask

Say what you want in the chat. The router reads the ask first and decides whether it is one small job or a plan of several.

2 · Work

The jobs run in isolated copies of your project (git worktrees), on the subscription that measured best for that kind of job.

3 · Check

Each task is verified, the related tests run, and the result carries a confidence reading with its reasons. You decide what lands.

What you need: Windows or Linux, git, and at least one of Claude Code, Codex, Cursor, Gemini or Grok signed in on that machine. To merge two subscriptions into one agent you need two usable ones; with one, antiloki runs solo, still routed per job. The optional browser test (QA) needs Chrome or Chromium.

2. Install

  • Windows: download the installer from the releases page and run it. The installer is not code-signed yet, so Windows SmartScreen may warn you: choose More info, then Run anyway.
  • Linux: download the .deb and install it, for example sudo apt install ./antiloki_<version>_amd64.deb, then start antiloki from your launcher. The current package needs glibc 2.44 or newer (Arch and other recent rolling distributions); wider support is in progress.
  • macOS: coming soon.

It is one program with no account. The 14-day trial starts on the first run and makes no network check. Downloads ask for your email once; see your data and privacy.

3. First run and setup

The first start opens a short setup. The first three steps cannot be skipped, because everything after them depends on them; the optional steps after that can.

  1. Theme. Pick a colour theme. You can change it later in Settings.
  2. Your AIs. It asks which subscriptions you have, each named for what it is (Claude Pro or Max, ChatGPT Plus or Pro for Codex, Cursor Pro, a Google account for the free Gemini tier). The tools already on your machine are ticked. For anything missing it shows the exact install line for your system (PowerShell on Windows, a terminal command on Linux) with a copy button. You run it yourself; antiloki never sees a password.
  3. Sign in. A tool that is installed but not signed in has a Sign in button. It opens a terminal window running that tool's own sign-in, which opens the vendor's page in your browser. antiloki never sees your credentials. Install or sign in elsewhere and come back: it rechecks every few seconds, and there is a "check again" button.
  4. Check. Each ready AI gets one tiny real call, so a broken sign-in shows up now and not on your first task. antiloki also reads how much of this week each subscription has used.
  5. Main provider. You choose which AI runs the chat and Heimdall, the router. It is chosen for you when only one is ready.

antiloki offers a provider only when the seat is real: a command-line program that sits on your machine unauthenticated is never offered. Then you open a project folder (any git repository) and the app is ready.

Short tours. The first time you reach a section of the app, a three-step card points at the things worth knowing. Each one shows once. "Welcome tour" in the search menu brings them all back.

4. The three screens

The switcher at the top has three screens, and every project has its own state in each.

Cowork
Where you talk to the agent and watch it work. The sidebar lists the agent's episodes; the Studio holds the tools you can place beside it.
X-ray
Code analysis: a health and risk verdict, every file scored, the architecture, the history, and a real code editor.
Sagas
The work, kept per project: goals, tasks and subtasks, who did each one, and what it cost.

At the top right a floating pill holds three instruments: your agents (one card each, wherever you are in the app), the money saved, and each AI's limits (the 5-hour and weekly windows where the vendor publishes them). The logo menu opens the search (jump to anything, run an action), your account, Settings, these docs, the rebuild button and the project switcher.

5. Working with the agent

The chat

The chat is a conversation that reads everything about the project: the code map, the earlier work, the goal runs. Before each answer a retriever picks what the ask needs and shows it under the reply as chips. Pin a chip to make it ride along in this session, drop it to keep it out. The conversation itself never changes your files; changes are made by the agent's runs, in a safe copy, and checked (see how a job is run).

The composer

  • @ references a card, a document, a code file or a live source.
  • # references a Studio tool.
  • /model switches the model of the current tier; /tier sets the router's tier.
  • The context button opens the context wizard: packs, scope, and the AIs' own memory files (read-only).

Episodes and forks

One agent works the whole project, and its sidebar is its episodes: each is a closed unit of work with the consolidation it came to. Close an episode to end a unit and start the next. Need a second line of work? Fork the agent: a new tab with its own worktree and its own episodes, closed when the work is done.

Scope and safety

An agent's scope is the set of files it may write, and it starts as the whole project; untick folders to narrow it. The scope is enforced by the tool: a write outside it is refused before the file changes, not discouraged in a prompt. Work happens in a worktree, not in your checkout, and one fence applies on every seat.

Commit and push

Under the chat input, Commit & push shows what would be committed, writes the message for you from what you asked and the files changed (or lets you edit it), and commits, or commits and pushes. antiloki's own files are never included.

Pull requests

Each agent box is one proposal: its branch against its base, the diff, mergeability, an AI summary and the blast radius. The queue is ranked by readiness. Merging does not touch your working tree. A goal run in write mode can open a pull request with the goal as the title and the joined report as the body.

6. How a job is run

Heimdall is the router that reads every ask before any model does.

  1. Grade. A small ask goes straight to one worker at the cheapest tier that can do it, with no planning round. A bigger ask is split into tasks that each own different files, laid out in waves. You can force this per run (never / always).
  2. Screen. Before planning, it asks what it cannot assume (one round of questions; defaults apply if you stay silent) and lists what it assumed on its own, so a wrong guess is one click to correct.
  3. Choose the seat. Each job goes to the subscription and model that benchmarked best for that kind of work. antiloki ships with 373 measured combinations (1,186 runs) as its starting table; your own runs add to it and never replace it. Seats whose window is exhausted are skipped, and the next best takes over until it resets.
  4. Work and verify. Workers edit in isolated worktrees. Each task is judged against its own acceptance by a second call at a higher tier; a strict reject sends it back once.
  5. Join and gate. When the last wave settles, one joined report lands in the chat, one change list rather than several branches. A write run ends at a QA gate that runs the related tests.
  6. Confidence. Every finished run shows high, medium or low with its reasons: whether the compiler or the project's tests passed, whether the verifier accepted the claims, how many attempts it took, whether a design rule failed. A button runs an independent QA on it when you want one: your ask tested in a real browser, filmed (or against the API for backend work). QA reports back without changing anything, and it costs nothing unless you press it.

Caution

If the router grades a route low, or a task touches credentials, billing, a database migration or a deploy file (or the ask says production, password, billing and the like), it uses a stronger model for that task. A tier you pinned yourself is never changed.

Approval

Ask me first holds the plan for your approval. Blocking questions park it for one answer round. The cost ledger prices every run against sending everything to the strongest model, and the difference is the saved money in the top-right pill; a failed run reports what it spent and claims no saving.

The rail

On an agent, the rail has three views of Heimdall: ⚡ Route (each ask's verdict, tier, model, how sure it was, and what the same turn would have cost raw), ? Screen (its questions and assumptions) and ⋔ Plan (the current plan by wave, and earlier ones).

7. X-ray

X-ray is the code analysis, and its right-hand sidebar has one icon per section.

Overview
The verdict: health and risk with their trend, the codebase as a map (each file a box; area is its mass, colour its health, five lenses), hotspots, and activity.
Code
The file tree, each file with its score and review, and a real editor (below).
Quality
The rules the code breaks and what the tests never reach.
Architecture
The system diagram and the import graph, with the blast radius of a change.
History
The review over time, the git graph, who wrote what.

A file's score is computed from your rules and measurements (tests, coupling, structure, change) with no model involved, so it is the same twice, and it tells you why a file is not 100. Everything measured here is also what agents receive as context. The ultra review tab is marked "soon".

The code editor

Open a file in Code and edit it: line numbers, syntax colours, search and replace, folding and undo. Ctrl/Cmd+S saves straight into your project. If the file changed on disk while you were editing (an agent, git), nothing is overwritten without asking, and what you typed is kept when you click to another file. After you save, the rebuild button says how many files were edited and that the analysis of them is out of date until the next rebuild.

8. Sagas

A saga is a titled goal. It holds tasks, and a task holds subtasks. Every ask you give the agent shows up here as a saga planned by Heimdall, and you can write your own: New saga takes a title, then add tasks and assign them to yourself, to Heimdall or to an agent. Agents read the list before they start, so work is not done twice.

  • Click a task's circle to move it on (todo, in progress, done); click its title to open it.
  • The activity trail says who did each step: you, Heimdall, or an agent with the exact model that ran. A task that failed shows its agent with a red ring.
  • Time, cost and tokens come from the real runs and roll up from the tasks to the saga.
  • A finished saga stays as a record: it can no longer be canceled or deleted.

9. The Studio

The Studio is the list of tools you can place beside an agent. Each has a live preview on your real data and an intro that says what it does and what it costs; "free" means it calls no AI. Open starts a fresh split with that tool alone; add drops it beside what you are looking at.

Issues
One tracker, Linear style: a list grouped by status, or a board. Statuses are Backlog, Todo, In Progress, Done and Canceled; each issue has a priority and a unique number (ISS-1, ISS-2…).
Notes
One page that saves itself. Markdown is drawn as you type, the way Obsidian does it: # makes a title at once, plus **bold**, - bullets, - [ ] checkboxes you can click, quotes and code blocks. The raw markdown comes back on the line you are editing.
Brainstorm
A simple chat for shaping an idea: pick what you want (what, where, how bold, what it must respect) as chips, say it in a line, and the plan lands on the shape pane. The planner's depth is chosen by the size of the ask.
Design canvas, Frames, Design system
Your running app captured as frames, the palette, type scale and spacing extracted from the code, and where a screen drifts from them. Edit a frame and turn the change into a prompt or an agent scoped to the files that own those tokens.
Git graph, Review, Gate, Run preview, Shell
The base branch with one lane per agent worktree; every worktree's diff in one place; the build and test gate; the project's dev server; a real terminal in the project or any worktree.
Fuel, Session timeline, Error radar
Live spend and limits per seat; the audit trail of every read, write, refusal and verdict; and the failure feed, grouped by pattern.

Issues, notes and the Brainstorm conversation are stored in your project's database (.antiloki/db/state.sqlite), not in the browser. Todos and cards from earlier versions are moved into Issues the first time you open it.

10. Settings

General
Your account and licence key, your AI engines (the subscriptions in use, and which model each tier maps to), optional own-key routes (off by default), the colour theme, the design check on QA, the code-analysis rebuild budget, and a reset for the project databases.
Benchmarks
Every measured combination the router uses. Each row says whether it is antiloki's default, measured on your machine, or both, and what it was measured on.
Earlier agents · Other CLIs
Other coding command-line tools, opened in a pane. They are never routed or priced.
Audit
The record of what the safety rules refused and every bypass that was granted.
Environments · Prompts · Statistics · Failures · Code checks
Where agents run their commands, the prompts in use, usage numbers, recorded failures, and which type checkers and linters the analysis may use.

Your licence key is entered under Account & profile (also in the logo menu), which is the first block of General.

12. Trial and licence

  • Trial: 14 days from the first run, everything included, no card and no account. Your projects stay when it ends.
  • Licence: one payment (planned: USD 499) for a lifetime licence with two years of updates and premium support. A build released inside your window keeps working for good. See the pricing section for the current state of checkout.
  • Activation: enter your key once in Account & profile (the first block of General in Settings). The app then works offline for up to 14 days between licence checks. To move to another computer, deactivate on the old one first.
  • If a trial has ended, the app shows the licence screen on every page, with the field for your key and the button to buy.

The terms have the legal wording.

13. Your data and privacy

antiloki is local-first: one program, no account, no telemetry. Your code and conversations stay on your machine, and there is no antiloki server in the path.

Project data
.antiloki/ inside each project, with its database at .antiloki/db/state.sqlite (chats, issues, notes, sagas, the code map).
App data
.antiloki in your home folder (on Windows, C:\Users\<you>\.antiloki): agent worktrees, benchmarks, limits, settings. The licence record lives in the operating system's app-data folder for antiloki.

The network calls it makes, all of them:

  • your command-line AI tools' own calls to their vendors;
  • a licence check once a day, once you have activated a key (the trial makes none);
  • an update check against a static file on GitHub Releases;
  • the window's fonts, from Google Fonts, when it opens;
  • api.openai.com or openrouter.ai only if you set up the optional OpenCode route with your own key;
  • GitHub only if you add a token or open a pull request.

Downloading an installer from this website asks for your email once; it signs you up for release news and offers (about one email every two weeks), and you can unsubscribe at any time. See the privacy policy.

14. Updates

The app checks for a new version against a signed file on GitHub Releases and offers to install it; updates are verified with a signature before they run. Every version, with its release notes, is on the releases page. The router's benchmark table is part of each release, so it stays current for the two years of updates a licence includes.

15. Troubleshooting

An AI is not offered
antiloki offers a seat only when it is signed in, not merely installed. Use the Sign in button in setup, or sign in with that tool in a terminal, then press "check again".
Windows SmartScreen warning
The installer is not code-signed yet. Choose More info, then Run anyway.
Linux: the package will not install or start
The current .deb needs glibc 2.44 or newer. Older distributions are not supported yet.
"License required" on every screen
Your trial has ended. Enter your key in the licence screen, or use the buy button.
The preview says "This content is blocked"
That was fixed in 0.5.4.1. Update to the latest version.
Cursor fails in the chat on Windows
Also fixed in 0.5.4.1. Update to the latest version.
The money chip is blank
It appears after the first check or the first routed task. Before that, nothing has been measured.
A conversation seems to be the wrong project's
Fixed in 0.5.4: each project has its own chats. Update to the latest version.
The code analysis is out of date after I edited files
That is expected: press rebuild. The button says how many files you edited.
Start from scratch
On Windows, tick "delete the application data" in the uninstaller. It removes the database, licence record and settings, so the first-run setup comes back.

16. Support
