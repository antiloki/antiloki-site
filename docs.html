Docs

antiloki is a free vibe graphing IDE: you describe the work, the Leader draws the team as a graph, and the loop runs it on the AI subscriptions you already have. These pages describe what the app does today.

1. Start here

Open a project folder, then ask the Leader for what you want. The Leader drafts a team as a graph of agents, tools, checks and gates. You edit the graph on the board, set the budget, and run it. Every node records what it did, with its agent, model, time and cost.

Antiloki runs on the CLIs you are already signed in to: Claude Code, Codex, Cursor, Gemini and Grok.

2. The Cowork screen

Cowork is where you work. Each agent runs in a real terminal pane, and you can split and arrange the panes. The Leader and the team's graph sit beside them.

  • Threads give each line of work its own git branch and worktree. Agents in a thread work on that branch, and you land the thread when you are ready.
  • Side questions open a read-only helper beside an agent, so you can ask about its work without interrupting it.
  • The Studio (the grid on the right) opens the other tools: Terminal, Brainstorm, Diff and review, Issues, Notes, Frames, Design system, Code graph, System design, Authors, X-ray, Constitution, Skill library, Code and Git graph.

3. Teams and graphs

A team is a graph of nodes and edges, edited on the board. The Leader is the one terminal agent in the graph, and there is exactly one per graph. The validator refuses a graph that cannot run safely: no Leader, a switch with no default port, or a loop with no cost cap.

Nodes
  • Agent: planner, worker, QA, debugger, audit, or your own agent with its own brief, skills and tools.
  • Tool: web search or page reading, or one of this app's own tools. Each tool node has an allow-list that names the tools it may use.
  • Fork and join: branches run side by side. The join waits for all of them, or for a quorum you set.
  • If and switch: route on what a node said. A switch needs a default port.
  • Loop: repeat a body until a condition holds. It needs a max count and a cost cap. Each pass is its own episode.
  • For each, retry: one branch per item, in parallel up to a limit; a failed node is sent round again, then takes its exhausted port.
  • Human gate: waits for your yes or no, with a timeout.
  • Artifact and deliver: artifacts are documents the run makes (a report, a draft). Deliver is the end of the graph.

Artifacts and skills

Artifacts are written to the project's .antiloki folder, and the next node reads them. Agents can propose changes to their skills. A proposal arrives as a draft, and nothing changes until you approve it.

4. Budgets and gates

Every loop needs a cost cap, and any node can carry its own. A run stops when it reaches its budget. Anything that leaves the project waits at a gate for your yes or no: a commit to your branch, a publish, a message to someone outside.

Agents only write inside the folders their node is allowed to touch.

5. MCP

Antiloki is an MCP server. An MCP client such as Claude Code can drive it through these tool families:

  • Threads and panes: antiloki_threads, antiloki_panes, antiloki_pane_open, antiloki_pane_read, antiloki_pane_send.
  • Teams: antiloki_teams, antiloki_team_design, antiloki_team_status, antiloki_team_simulate.
  • Sagas: antiloki_sagas, antiloki_saga_add, antiloki_episode_add, antiloki_episode_update.
  • X-ray: antiloki_xray, antiloki_xray_rebuild, antiloki_xray_open.
  • Other: antiloki_delegate, antiloki_worktrees, antiloki_frame_create, antiloki_rules, antiloki_qa.

Tool names are as the server registers them today. Ask the client to list the tools to see the full set.

6. Web apps

Web apps open in their own pane, from a store, beside your agents. A graph can also use the web node, which searches the web and reads a page for the agent that asked.

7. The X-ray

The X-ray is a health view of the repo, built from the codebase itself.

  • Verdict row: health, risk, files judged, test coverage, the share of files one person owns, and vulnerable dependencies.
  • Health over time: health and risk per snapshot.
  • Hotspots: files plotted by gravity (how much code leans on them) and churn (how often they change), coloured by health.
  • The codebase: every file is a box, sized by its mass. Pick a lens to colour the map: health, cascade (what breaks with it), ownership, debt, heat, or runtime coverage.
  • Laws broken most and movers since the previous snapshot.

Rebuild the X-ray after large changes. The Leader can read it, so "why is this file scored low?" gets a real answer.

8. Sagas

A saga is a goal and the episodes that get it done. Sagas are listed by project, as a list or a board, and grouped by status: in progress, todo, failed and done. Each row shows the progress, the cost and when it last changed. A finished saga stays on the record, so the history cannot be deleted.

9. Your AI seats

Antiloki offers only the providers you are actually signed in to. It reads the seat, not the installed binary, so a CLI on your machine that is not signed in is never offered. One subscription is enough. A team can use more than one seat, for example a planner on one and workers on another.

10. Install and status

Downloads are coming soon for Windows, Linux and macOS. Nothing here needs an account.

11. Privacy

There is no account and no telemetry. The network calls are your CLIs' own calls, an update check against a static file on GitHub Releases, and the fonts this page loads from Google Fonts.
