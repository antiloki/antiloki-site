antiloki · documentation

antiloki docs.

Everything antiloki does today, in the order you meet it: install, set up, work, teams that draw themselves and improve by experiment, specialists, models on your machine, and what to do when something does not behave. Updated 2026-11-23.

1. Start here

antiloki is a vibe graphing IDE: a desktop app where you describe the work in plain words to a Leader, it draws a team as a graph of agents, tools, checks and approval gates, and the team runs on the AI subscriptions you already pay for (Claude, Codex, Cursor, Antigravity, Grok). You watch it write the code, look at the running result, and decide what lands in your project.

It does not replace those tools and it has no model of its own. It runs each one through its own command-line program, signed in the way you already are, so there is no API key to paste and no extra account.

1 · Describe

Tell the Leader what you want. It drafts a team as a graph; you read it, edit it on the board, or start from a template.

2 · Run

Each agent works in an isolated copy of your project (a git worktree) on a seat of yours; the parts that need no model (tests, build, lint) run as plain code.

3 · Watch and approve

See the files being written in the Editor view and the app running in the Preview; a gate stops the run until you approve. Nothing reaches your branch without it.

What you need: Windows or Linux, git, and at least one of Claude Code, Codex, Cursor, Antigravity or Grok signed in on that machine. To merge two subscriptions into one agent you need two usable ones; with one, antiloki runs solo, still routed per job. The optional browser test (QA) needs Chrome or Chromium.

2. Install

  • Linux: download the AppImage from the latest release, make it executable (chmod +x) and run it. A .deb is not part of every release.
  • Windows: the installer is not released yet; the latest release has no Windows file. It is on the way.
  • macOS: there is no macOS build and none is planned for now.

It is one program with no account, no trial and no key: it is free and open source (Apache-2.0). You also need git and at least one AI CLI signed in; see your data and privacy. To build it yourself, see the source.

3. First run and setup

The first start asks which folder you want to work in (any git project, new or one you already used with antiloki). Then a short setup of six steps opens. Nothing in it blocks you: you can continue at every step, even with no AI installed yet, and come back to any of it later in Settings.

  1. Theme. Pick a colour theme. You can change it later in Settings › Appearance.
  2. Your AIs. It asks which subscriptions you have, each named for what it is (Claude Pro or Max, ChatGPT Plus or Pro for Codex, Cursor Pro, a Google account for Antigravity). The tools already on your machine are ticked. For anything missing it shows the exact install line for your system (PowerShell on Windows, a terminal command on Linux) with a copy button, and how to sign in. You run it yourself; antiloki never sees a password. It looks again every few seconds, and there is a "check again" button. Here you also choose the main provider, the AI that runs the chat and Heimdall, the router (it is chosen for you when only one is ready).
  3. Check. Each ready AI gets one tiny real call, so a broken sign-in shows up now and not on your first task. antiloki also reads how much of this week each subscription has used. With no AI ready it says so and tells you to go back one step.
  4. Git credentials (optional). A token, only to open pull requests from antiloki. Skip it and everything else works.
  5. Build the X-ray. One analysis indexes the code and draws the maps. It runs in the background, and you can continue while it builds.
  6. Ready. A short summary of Cowork, Teams, Sagas and X-ray, and you are in.

antiloki offers a provider only when the seat is real: a command-line program that sits on your machine unauthenticated is never offered. The setup is remembered by the browser or app window you ran it in, so a different browser, or cleared site data, starts without it.

Short tours. The first time you reach a section of the app, a three-step card points at the things worth knowing. Each one shows once. "Welcome tour" in the search menu brings them all back.

4. The screens and the bars

Cowork is the screen you live in; Sagas and X-ray are one click away. Every project has its own state in each.

Cowork
Where you talk to agents and watch them work. Each project is a space with threads; a thread is a set of panes laid out the way you like: terminals, agents, specialists, teams, browsers, Files, your web apps and pages made for you. The panes use the whole width of the window.
Sagas
The work, kept per project: goals, tasks and subtasks, who did each one, and what it cost.
X-ray
The analysis of the code: the verdict, the maps, a score for every file, the rules and the history.

The menu is the a. at the right of the bottom bar. A click opens it in the middle of the screen: spaces, threads, agents and their sagas, search and these docs. The bottom bar holds, from the left: the discreet icons (commit, push, light browser, full browser, Files, terminal); the time and cost of the team you are in (click it for the waterfall); then, at the right, the money, each AI's limits, the machine and the menu. Click the money for the usage window and the three small bars for the machine window.

5. Working with the agent

The chat

The chat is a conversation that reads everything about the project: the code map, the earlier work, the goal runs. Before each answer a retriever picks what the ask needs and shows it under the reply as chips. Pin a chip to make it ride along in this session, drop it to keep it out. The conversation itself never changes your files; changes are made by the agent's runs, in a safe copy, and checked (see how a job is run).

The composer

  • @ references a card, a document, a code file or a live source.
  • # references a pane or tool.
  • /model switches the model of the current tier; /tier sets the router's tier.
  • The context button opens the context wizard: packs, scope, and the AIs' own memory files (read-only).

Episodes and forks

One agent works the whole project, and its sidebar is its episodes: each is a closed unit of work with the consolidation it came to. Close an episode to end a unit and start the next. Need a second line of work? Fork the agent: a new tab with its own worktree and its own episodes, closed when the work is done.

Scope and safety

An agent's scope is the set of files it may write, and it starts as the whole project; untick folders to narrow it. The scope is enforced by the tool: a write outside it is refused before the file changes, not discouraged in a prompt. Work happens in a worktree, not in your checkout, and one fence applies on every seat.

Commit and push

Under the chat input, Commit & push shows what would be committed, writes the message for you from what you asked and the files changed (or lets you edit it), and commits, or commits and pushes. antiloki's own files are never included.

Pull requests

Each agent box is one proposal: its branch against its base, the diff, mergeability, an AI summary and the blast radius. The queue is ranked by readiness. Merging does not touch your working tree. A goal run in write mode can open a pull request with the goal as the title and the joined report as the body.

6. How a job is run

Heimdall is the router that reads every ask before any model does.

  1. Grade. A small ask goes straight to one worker at the cheapest tier that can do it, with no planning round. A bigger ask is split into tasks that each own different files, laid out in waves. You can force this per run (never / always).
  2. Screen. Before planning, it asks what it cannot assume (one round of questions; defaults apply if you stay silent) and lists what it assumed on its own, so a wrong guess is one click to correct.
  3. Choose the seat. Each job goes to the subscription and model that benchmarked best for that kind of work. antiloki ships with 373 measured combinations (1,186 runs) as its starting table; your own runs add to it and never replace it. Seats whose window is exhausted are skipped, and the next best takes over until it resets.
  4. Work and verify. Workers edit in isolated worktrees. Each task is judged against its own acceptance by a second call at a higher tier; a strict reject sends it back once.
  5. Join and gate. When the last wave settles, one joined report lands in the chat, one change list rather than several branches. A write run ends at a QA gate that runs the related tests.
  6. Confidence. Every finished run shows high, medium or low with its reasons: whether the compiler or the project's tests passed, whether the verifier accepted the claims, how many attempts it took, whether a design rule failed. A button runs an independent QA on it when you want one: your ask tested in a real browser, filmed (or against the API for backend work). QA reports back without changing anything, and it costs nothing unless you press it.

Caution

If the router grades a route low, or a task touches credentials, billing, a database migration or a deploy file (or the ask says production, password, billing and the like), it uses a stronger model for that task. A tier you pinned yourself is never changed.

Approval

Ask me first holds the plan for your approval. Blocking questions park it for one answer round. The cost ledger prices every run against sending everything to the strongest model, and the difference is the saved money in the top-right pill; a failed run reports what it spent and claims no saving.

The rail

On an agent, the rail has three views of Heimdall: ⚡ Route (each ask's verdict, tier, model, how sure it was, and what the same turn would have cost raw), ? Screen (its questions and assumptions) and ⋔ Plan (the current plan by wave, and earlier ones).

7. Sagas

A saga is a titled goal. It holds tasks, and a task holds subtasks. Every ask you give the agent shows up here as a saga planned by Heimdall, and you can write your own: New saga takes a title, then add tasks and assign them to yourself, to Heimdall or to an agent. Agents read the list before they start, so work is not done twice.

  • Click a task's circle to move it on (todo, in progress, done); click its title to open it.
  • The activity trail says who did each step: you, Heimdall, or an agent with the exact model that ran. A task that failed shows its agent with a red ring.
  • Time, cost and tokens come from the real runs and roll up from the tasks to the saga.
  • A finished saga stays as a record: it can no longer be canceled or deleted.

8. Panes

Everything beside the agent is a pane. The + menu opens a terminal or an agent, Sagas, your web apps and Your panes; Make a new pane… starts the dialog below.

Web apps in a pane

Linear, Notion and GitHub have a pane each. You connect once (a token you paste in the pane's own Connect screen, never in chat, or the app's own sign-in); the token stays on your machine. Each pane reads and edits the app: a list, a board, a page, files with their code coloured. When the app refuses, the pane says exactly why and links to where you fix it: an expired or missing token, a missing permission, an organisation that needs single sign-on.

Make a new pane

A new pane is always made by a team, from a template; nothing here opens a pane that already exists.

Web app
Pick an app you connected and say what the pane should show or do. A team reads the app's real tools, designs a small pane, stops for your approval of the design, then writes the pane as a draft.
Web app, recreated
The REA team studies a web app in a window you sign in to once, you approve the design before any code, and the pane is made at the end.
Deterministic
Say what you want to see. A team finds the right zero-AI data source, previews it, stops for your approval and saves a widget to your board. No code is written.
Specialist
An agent with a memory of its own, tools of its own and a brief. See Specialists: ask any agent to make one, and it waits under + › Waiting for your approval until you read it and approve it.

Your panes (free panes)

A free pane is a folder, .antiloki/panes/<id>/, with a manifest and a page. A person, an agent or a team can write one; only you approve it. A draft shows a card that lists who made it, what it is for, which apps it talks to and exactly which tools it may read and write. The page runs in a sandbox with no network of its own: everything it knows comes through antiloki, which checks the manifest again on every call. A pane that was edited by anyone is a draft again.

  • Reading an app works once you approved the pane, and only through tools that only read.
  • Writing never happens without your click. antiloki draws its own card outside the page, with every argument in words; a destructive tool needs a second tick; declining tells the page "declined". Every confirmed write is logged.
  • A pane keeps its own memory, can show an app's pictures, open a link (asked once per domain) and show a short notice in its header.
  • Export (in the pane's header) saves a pane as one file; Import a pane… (in Your panes) brings one in as a draft, so approval is asked again. A file changed after it was exported is refused, and nothing is overwritten.
  • Agents read a free pane by meaning (what it shows, which controls it has) and act in it through the same code a click uses, so a write still asks you.

Over MCP an agent can write and open a draft (antiloki_free_pane_write, _open, _list), read an installed app's tools (antiloki_app_tools) and read or act in a pane (antiloki_pane_view, antiloki_pane_act). It cannot approve.

9. No settings page

antiloki has no settings page and no setup wizard. Open a folder and you are in Cowork. The seats are detected from what is already installed and signed in on the machine, and the agents run in real terminals, so anything you would configure is configured in the tool itself. Earlier versions had screens for benchmarks, audit, environments, prompts, statistics and more; they were removed in v1.0.

11. Free and open source

  • antiloki is free: no trial, no key, no plan, no account. Nothing is locked and nothing is sent to be checked.
  • The source is published under the Apache-2.0 licence: antiloki-app (the app) and antiloki-ui (the front end). Contributions are welcome; start with CONTRIBUTING.md in the app repository.
  • It is built and kept going by a small team. If it saves you time, supporting it on Patreon or buying a coffee helps us keep working on it: more fixes, a Windows build, faster releases.

The terms have the legal wording.

12. Teams and templates

A team is a graph of agents, tools, checks and gates that runs on your subscriptions. New team offers ready-made templates:

Recreate a web app
Studies a signed-in web app and rebuilds it as a pane (verified by a real run).
SEO audit · Marketing campaign · Lead capture · Sales follow-ups
Each stops for your approval; nothing is sent, published or changed in your apps (each proven by one real run, about a cent or two).
Bug hunter
Builds and tests your project, maps the risky spots, hunts security and logic bugs (every finding needs a file and line), writes a failing test for each, runs them, reads the app in the browser, and writes a ranked report. Your code is not changed.
Pane for a web app · Deterministic widget
The teams behind Make a new pane.

Verified means a real run of that template finished; draft means it has not run yet. Share as template turns a team of yours into a template after checking it carries no secret and no path of your machine, and resetting its triggers and limits.

The team's bar

The bar of a team has four views, Chat, Graph, Editor and Sequence, and a few icons: Fork (the same team on another engine, and the threads you have), the sagas of the team, Evolve (the DNA) and Swarm (the bee). The pane's top bar is the only menu: there is no floating menu and no Edit, Activity, Sagas, Result or X-ray tab.

The Leader (Chat)

Every team has a Leader: the terminal or chat you talk to, which drafts and edits the team, starts runs, reads the results and repairs a failed run. Chat is the first view of the bar. The Leader can also sit beside the team (about a third of the width, resizable) or float as a window you can drag and resize that turns see-through when the pointer leaves it; with either on, moving the pointer over it puts the keyboard in it and moving away gives it back to the pane you were in.

Watching a run: Graph, Editor, Sequence

Graph is the circuit, node by node. Every node carries a small number, its place in the order the team runs (parallel steps follow one another), and every branch that a fork, an if, a switch or a for-each starts has a colour of its own on its lines, until the branches join again. Click a node to open it and change its settings there: editing happens on the graph; the full editor with the palette of nodes opens from the graph's edit button. Sequence is the order things happened, as lanes over time. Editor is the code: a file explorer, tabs, and the editor itself, where every agent is a named, coloured pointer typing its files, read-only while they work. The sagas of the team and what a run changed are one click away on the top bar and in the nodes.

The Preview node

A preview node starts the project the team is building (its dev or start script, or its main file), waits for the address it prints and keeps it running until the run ends. A frontend shows as a live frame in the Editor view; a backend shows its address and log. Put it before an approval gate to look at the real thing before you approve. It costs nothing (no model).

The book: laws for any kind of work

A team of agents becomes a team when something that is not a model judges its work. The book is that judge: a set of laws written as data, run by plain code, the same answer every time. It is not only for code: it reads markdown, plain text, web pages, JSON, YAML, TOML, tables (CSV), images and SVG, and it judges copywriting, reports, plans, data and graphics with the same rules of the road.

  • Packs ship for technical documents, marketing copy (English and Portuguese), SEO reports, project plans, tables, web pages and images; each law has examples that prove it. Yours go in .antiloki/book/ and replace a shipped pack of the same name.
  • The Leader writes the laws for the work in front of it (a length, a banned phrase, a required section, a field that must exist, an image size), tests them against their own examples, and shows you how often they fire. They start as candidates: advice that never gates.
  • You ratify. Open the Book in the Editor view; a law without a passing and a failing example cannot be ratified, and the button says why. Only ratified laws gate.
  • The law-gate step judges what a node made and routes pass or fail: a failure sends the findings (a file, a line, the number found against the number expected, and a fix) back to the agent that must repair them. If no law applies to the files, the gate says so; it never reports a pass it did not earn.
  • The Findings tab of the Editor's bottom panel shows the same report live while agents write. It costs nothing and calls no model; the same files and laws give the same report, byte for byte (it carries a digest you can compare).
  • Over MCP: antiloki_book (list, show, run, test, propose). An agent can propose laws; ratifying is yours.

Building teams

  • The editor has a Blank node (an agent you describe in words) and Turn it into… any other kind of node.
  • Branches are reusable groups of nodes: save the selected node, with or without everything after it; add one to a team as its own copy.
  • A sub-team node runs another team as one step. Several run side by side after a fork; an inner team's approval appears in the parent's list, and the parent does not time out while it waits for you.
  • A node that calls no model carries a det flag: the same input always gives the same output.
  • The lint node downloads a pinned checker (TypeScript, ESLint, Ruff, Clippy, go vet) the first time and runs it, so the verdict is the same on every machine.
  • A step whose agent says it could not finish fails; the run stops there instead of reaching your approval with nothing to approve.

Over MCP: antiloki_team_templates (list, or make a team from one), antiloki_team_branch, antiloki_team_graph and the other team tools.

13. Evolve and Swarm

A team can improve itself by experiment, not by hunch. Two icons on the team's bar: the DNA is Evolve, the bee is Swarm. Each opens a small panel with two pages, Setup and Results.

Evolve: Setup
Choose what should get better (cheaper, faster or better), the least gain (20% by default; a small picture shows what it means in your numbers), how many ideas to try, and the budget. The panel says what one idea costs (measured from your last session), whether the budget covers the ideas you asked for, and what your tests are: it needs at least one practice and one held-out test (save a passed run as a test first).
How an idea is judged
The improver proposes one change at a time (a cheaper model for a step, different instructions, a different order). Each is run beside today's version on your own tests: a screen first, then repeated runs on tests the improver has not seen. It is accepted only if the gain, with the run-to-run noise counted, clears your line and the pass rate holds. A gain that could be luck is refused, and the reason is written down.
Evolve: Results
A ring for the money spent, the four stages (propose, screen, race, verdict), a gain meter for each idea (the bar is the measured gain, the whisker is the noise, the dashed line is your goal) and the versions of the team. When a session ends, two glass boxes with the same meters and a table of the trials float over the graph's bottom right.
Swarm
Tests several ideas at the same time. Setup: how many run at once (sockets; the panel marks how many this machine holds), how many ideas per round, and the live state of your machine. Results: the sockets with what runs in each, the ideas waiting for one, and a bracket with a square per run. The best idea that passes is applied; two that both pass are never merged blind, the second is refused with the reason and can be tried again on top.
Safe by design
Every session has a budget and a stop. The machine guard (below) pauses the runs of a swarm when RAM or CPU is short, and the panel says so. Each finished session sends a full report to the Leader, and the Leader can start, tune and stop both over MCP (antiloki_team_improve: evolve_* and swarm_* operations).

14. Specialists

A specialist is an agent with a job: its own memory (a database of notes and the conversations it had), a brief, skills (the kinds of task it does, each with a prompt), tools of its own and read-only antiloki tools, an avatar and limits. It is not a skill file.

Making one
Say make a specialist in X to any agent. It proposes the whole thing at once (antiloki_specialist_create). A proposal that breaks a rule is refused with every broken rule and nothing is stored; a good one is saved as a draft.
Approving one
A draft waits under + › Waiting for your approval. A click opens its editor: read it, change what you want, and save: saving approves it. An agent that is asked to open a draft opens that editor for you. Only after approval does it appear in the + menu as a pane you can open.
The rules of a good one
A purpose (40+ characters), a persona (80+), at least two different skills, something deterministic (a tool of its own or a pack of the book), at least two seed notes, and limits. Tools of its own are written in Rhai, a small scripting language (not JavaScript): input is the argument, the last expression is the answer, == compares, s.trim(); changes the string in place; helpers: read_file, matches, find_all, json, word_count. A refusal carries this hint and the tool's own description lists the whole rubric with a worked example.
Tools it may be given
Only read-only, deterministic antiloki tools (query, sources, file and folder review, blast radius, tests for, check, laws, book, specialist, machine, cost). It cannot use Drive, Calendar, the browser or anything that writes: it prepares the work and you, or an agent, do the rest.
Memory
Project (shared with whoever has the folder) or private (in your own folder). The pane's conversation is kept as it goes and consolidated into notes.

15. Models on this machine

A model that runs on your own computer (through Ollama) is an agent like any other: open a pane on it from the + menu, make a specialist from it, or switch a specialist to it. It is the same agent with the same tools and the same gate; the local server only replaces the brain.

  • A model your Ollama is too old to load (for example the lfm3 family needs Ollama 0.40.13 or newer) is shown greyed out with the reason instead of failing when you open it.
  • When a pane switches away from a local model, antiloki asks Ollama to drop it from memory at once.
  • If the model server keeps the CPU above 2.5 cores for half a minute, the panes on a local model say so. A smaller model, or a cloud seat, is lighter. Without a GPU, one local model at a time is the sensible limit.

16. Keyboard, looks and windows

The leader key
Ctrl+Space, then a key: T terminal, A agent, S specialist, B light browser, Shift+B full browser, F files, W close the pane, Q remove the thread (asks first), 1 to 0 go to a thread. Up and Down roll a small dial of the threads, Enter goes, Esc cancels. The leader key and every binding can be changed in the keyboard menu at the bottom bar.
Looks
Appearance has four looks (pixel, shadow, liquid, minimal), the opacity of panes and terminals, a wallpaper and every Omarchy theme found on the machine, each applied live.
Windows
Every window and menu of antiloki (the menu, usage, appearance, the model picker, the panels of Evolve and Swarm, time and cost) is one glass shell in the theme's colours; they open from where you clicked with a short grow-in.
Teams drift
A thread works in its own git tree. A chip on the team's bar says when the workspace has moved on (how many commits and files) and Update from the workspace merges them in.

17. Usage, cost and the machine

The usage window

Click the money in the bottom bar. One window shows the last Today, 7 days or 30 days and the measure you pick: cost, tokens or requests.

  • Cost is what the same tokens would cost at OpenRouter's list prices (subscriptions bill $0 metered), with the prompt cache counted at its own rates, plus what team runs spent. A model that is not on the list is marked "no price", never guessed.
  • It is read from what really ran: the session files of Claude Code and Codex, plus antiloki's own calls. Other seats are not read yet.
  • Your asks branch into one line per model, each as wide as its share; stacked bars per company; each seat's 5-hour and weekly limit with an "out of quota" line when one is out; every model with its price in and out per 1M tokens; and the cost per day.

Time and cost of the team

On the left of the bottom bar, after the icons, a small reading shows how long the team you are in has run and what it cost (a dot pulses while it runs). Click it and the full Time and cost waterfall opens in the middle of the screen as a glass window: every step as a bar, with its model, time and cost. Escape closes it.

The machine

The three bars in the bottom bar show CPU, RAM and VRAM. They turn amber at 80% and red at 92%, where a machine starts to swap and agents stall. The window shows rings, the last two minutes, advice that names the heaviest process, and who is using it; with Ollama running it offers Unload local models (asks first, frees the memory, keeps the model files). A number the machine cannot report is a dash, never a zero.

The machine comes first. Every background run (an experiment of Evolve or Swarm, a goal task, an X-ray call) is watched. When free memory falls under about 2.5 GB (15% of the RAM, whichever is more) or the CPU is over-booked, antiloki pauses one run at a time (nothing is lost) and continues them one at a time once there is room again (over 4 GB or 25% free, and a calm CPU). A new run does not start while the machine is short. A local model that keeps the CPU above 2.5 cores for half a minute says so in its pane, and a model a pane leaves is unloaded from memory.

Over MCP: antiloki_machine and antiloki_cost, so an agent can check the machine before starting a heavy model and read what it is costing.

18. Your data and privacy

antiloki is local-first: one program, no account, no telemetry. Your code and conversations stay on your machine, and there is no antiloki server in the path.

Project data
.antiloki/ inside each project, with its database at .antiloki/db/state.sqlite (chats, issues, notes, sagas, the code map).
App data
.antiloki in your home folder (on Windows, C:\Users\<you>\.antiloki): agent worktrees, benchmarks, limits, settings. The licence record lives in the operating system's app-data folder for antiloki.

The network calls it makes, all of them:

  • your command-line AI tools' own calls to their vendors;
  • no licence check: there is no licence;
  • an update check against a static file on GitHub Releases;
  • the window's fonts, from Google Fonts, when it opens;
  • api.openai.com or openrouter.ai only if you set up the optional OpenCode route with your own key;
  • GitHub only if you add a token or open a pull request.

Downloading antiloki asks for nothing: the download is a direct link to GitHub Releases, with no form and no email.

19. Updates

The app checks for a new version against a signed file on GitHub Releases and offers to install it; updates are verified with a signature before they run. The update file currently lists the Linux AppImage only; there is no Windows build to update yet.

20. Troubleshooting

An AI is not offered
antiloki offers a seat only when it is signed in, not merely installed. Use the Sign in button in setup, or sign in with that tool in a terminal, then press "check again".
Windows SmartScreen warning
The installer is not code-signed yet. Choose More info, then Run anyway.
Linux: the package will not install or start
The current .deb needs glibc 2.44 or newer. Older distributions are not supported yet.
"License required" on a screen from an older build
Update to the current version: antiloki is free now and has no licence screen.
The preview says "This content is blocked"
That was fixed in 0.5.4.1. Update to the latest version.
Cursor fails in the chat on Windows
Also fixed in 0.5.4.1. Update to the latest version.
The money chip is blank
It appears after the first check or the first routed task. Before that, nothing has been measured.
A conversation seems to be the wrong project's
Fixed in 0.5.4: each project has its own chats. Update to the latest version.
The code analysis is out of date after I edited files
That is expected: press rebuild. The button says how many files you edited.
Start from scratch
On Windows, tick "delete the application data" in the uninstaller. It removes the database, licence record and settings, so the first-run setup comes back.
